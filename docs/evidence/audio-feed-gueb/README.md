- Actual production code path: `src/worker/synthesis.ts` creates `GeminiTtsClient` without a model override; `src/tts/gemini.ts` chooses `gemini-3.8-flash-tts`. The separate grounded script stage defaults to `gemini-3.8-flash` with `maxOutputTokens: 4096`. There is no model env override in `src/config.ts`. Paul's exact `Gemini API error:` prefix is exclusive to the TTS HTTP error handler, not the script call. The 8192 cap therefore points to the TTS model, **not** an old text model.
- **Before:** one unsegmented TTS request contained 47,044 UTF-8 bytes of transcript (`title` plus article); model `gemini-3.8-flash-tts`, temperature `0.7`, `maxOutputTokens` unset. The original request shape was sent through `GeminiTtsClient.sendRequest` to an injected HTTP-400 API response carrying Paul's exact `The input token count exceeds the maximum number of tokens allowed (8192).` error. This is a local HTTP-response reproduction, **not** evidence the actual provider rejected this specific article.
- **After:** eight ordered TTS requests to `gemini-3.8-flash-tts`; transcript UTF-8 byte lengths `[5999,5998,5991,5994,5994,5999,5994,5067]`, all below the 6000-byte budget. Temperature `0.7` and explicit `maxOutputTokens: 16384` on each request. Mocked PCM is joined into one RIFF WAV; dialogue segment speaker metadata is retained and incompatible audio fails closed.
- **Token counts:** Exact provider `countTokens` results are **unavailable**: `GEMINI_API_KEY` is not set on this lane. Byte counts are not exact token counts. The error reports `estimatedInputTokens<=N (UTF-8-byte bound)` as a conservative approximation, not an API-measured count. Verify actual model limits, acceptance of `maxOutputTokens: 16384`, true token counts, speech quality and seamless playback with a credential-enabled lane before claiming live verification.
